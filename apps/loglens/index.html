面试要点 · 分布式日志排查方法论
先对表再对账：跨服务日志先校准时钟（NTP 偏差会把时间线骗过你），再按 traceId 串链路——
  本工具假设时钟可信，真实生产建议日志里直接落 traceId + 相对耗时（耗时比绝对时间戳更抗时钟漂移）。
看 gap 不只看 error：ERROR 是结果，gap 才是过程——两个服务之间突然多出 800ms，
  要么是网络，要么是对方在「悄悄干活」（慢 SQL / GC / 锁等待）。
重试是放大器：下游一次 1.4s 的锁等待，被上游重试两次后，用户端变成 3.8s——
  在瀑布图上能看到同一动作的三条平行泳道几乎同步重叠，这是容量事故的经典前兆。
日志级别治理：ERROR 该报警、WARN 该被看见、INFO 该能对出链路、DEBUG 该在生产关掉——
  四个级别各自失效的方式都不一样。
